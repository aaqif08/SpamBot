# API reference (v1)

Base path: `/api/v1`. OpenAPI 3 documentation is generated by the backend at `/docs` (Swagger UI), `/redoc` and `/openapi.json`; it is enabled outside production and can be turned on in production with `BOTSHIELD_DOCS_ENABLED=true`. The Pydantic schemas live in `backend/app/schemas/api.py`; the TypeScript mirrors in `frontend/src/types/api.ts`.

## Conventions

- **Authentication.** `POST /auth/login` returns a short-lived JWT access token (`Authorization: Bearer …`, 30 min by default) and sets an httpOnly, `Secure`, `SameSite` refresh cookie scoped to `/api/v1/auth`. `POST /auth/refresh` rotates the cookie and issues a new access token; `POST /auth/logout` revokes it. Changing a password invalidates all existing tokens.
- **Authorization.** Roles `ADMIN` > `ANALYST` > `VIEWER`. Every record belongs to an organization; requests can only see their own organization's data (enforced server-side on every query).
- **Errors.** `{ "detail": string, "code": string }`. Validation errors (422) add `errors: [{loc, msg, type}]`; server errors (500) add `request_id`. Every response carries `X-Request-ID`.
- **Rate limits.** Per-IP API limit, per-user ML limit (`/analyses`, `/batches`, `/models/train`, `/providers/*/fetch`) and a per-IP+email login limit; `429` responses include `Retry-After`.
- **Jobs.** Long operations return `202` with a job id; poll `GET /jobs/{id}` (`status` QUEUED → PROCESSING → COMPLETED | FAILED, with `progress`, `stage`, `message`, `log[]`, `result`).

## Endpoints

### System (public unless noted)

| Method | Path | Notes |
|---|---|---|
| GET | `/health` | liveness: `{status, version}` |
| GET | `/health/ready` | readiness: database, migration revision, storage; `503` when not ready |
| GET | `/research` | citation, paper-reported results (clearly labelled as such), feature groups, pipeline |
| GET | `/runtime` | *(auth)* environment, job/storage backends, library versions, production model |
| GET | `/features` | *(auth)* feature catalogue (31 features, groups, descriptions) |
| GET | `/dashboard` | *(auth)* cards + charts computed from the organization's own records |
| GET | `/jobs`, `/jobs/{id}` | *(auth)* background jobs of the organization |
| GET | `/providers` | *(auth)* `manual`, `csv`, `x_api` with `configured` flags |
| POST | `/providers/{name}/fetch` | *(ANALYST)* `{identifier}` → `AccountInput`; `409` "External data integration is not configured" when the provider lacks credentials |
| GET | `/audit` | *(ADMIN)* paginated audit log (`action`, `actor`, `page`, `page_size`) |

## `AccountInput`

Raw profile counts and flags plus optional aggregated tweet statistics or the tweets themselves; derived features (ratios, entropy, sentiment, …) are always computed server-side by the same `FeatureExtractor` used in training.

```json
{
  "account_id": "example", "screen_name": "example", "name": "Example",
  "verified": false, "friends_count": 120, "followers_count": 15, "listed_count": 0,
  "favorites_count": 50, "statuses_count": 500,
  "description": "…", "location": "", "url": null,
  "default_profile": true, "default_profile_image": false, "geo_enabled": false,
  "profile_background_tile": false, "has_profile_banner": false,
  "hashtag_count": 25, "mentions_count": 40, "retweet_count": 300, "reply_count": 2, "url_count": 20,
  "tweets": ["…", {"text": "…", "retweet_count": 3}]
}
```

## Risk score wording

`risk_score = round(100 × P(bot))` and `risk_band` are derived from the model probability. Every `AnalysisResponse` carries `risk_score_note` stating that the value is a model output, not a verified fact, and the UI labels results as "Classified as BOT/HUMAN" and "Estimated bot probability".
